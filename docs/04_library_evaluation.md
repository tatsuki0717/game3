# 04. ゲーム系ライブラリ導入の検討

> 2026-10 時点の検討メモ。結論は「§5 推奨案」。

## 1. 現状

- 描画は素の DOM + CSS（`src/ui/`、約 1,000 行）。毎回 `render()` で画面全体を作り直す即時モード的な構成。
- ロジックは `src/core/`（DOM 非依存の純粋 TS、reducer + シード付き乱数）。テストとシミュレータはここだけを使う。
- 未実装で、ライブラリが効いてくる項目（`02_game_design.md` / `03_technical_design.md` M6 より）
  - 机の上で品物・書類を**ドラッグ**して並べる・重ねる（Papers, Please 式）
  - **ルーペ**での拡大表示、**UV ライト**で透かしが浮かぶなどの視覚演出
  - **サウンド**（BGM・SE）、客の出入り・判子・お金のアニメーション
  - アート差し替え（スプライト・画像アセットの読み込み）

逆に、規則帳・カタログ・新聞・夜の帳簿・交渉ログなど**日本語テキストが多い UI** は DOM のままが有利（組版・折り返し・スクロール・入力欄・レスポンシブ・Playwright での自動テスト）。この点は当初 Phaser をやめた理由でもある。

## 2. 候補

| ライブラリ | 版 (npm) | 種類 | 得意なこと | このゲームでの懸念 |
|---|---|---|---|---|
| **Phaser** | 4.2.1 | フルエンジン | シーン、入力、ドラッグ、Tween、オーディオ、ローダ、カメラが全部入り | テキスト主体 UI を Canvas で作り直すと工数大。DOM との混在がぎこちない。バンドル大（gzip で数百 KB）。全面移行が前提になりやすい |
| **PixiJS** | 8.22.0 | 2D レンダラ | WebGL/WebGPU 描画、フィルタ（ぼかし・色変換・マスク）、イベント（ドラッグ）。**画面の一部に埋め込める** | シーン管理・音・Tween は別途。描画以外は自前 |
| Excalibur | 0.32.0 | フルエンジン | TS ネイティブ、物理・アクター | 0.x 系で API 変動あり。アクション寄り |
| KAPLAY | 3001.0.19 | 軽量エンジン | 手軽な 2D アクション | アクション/ジャム向け。UI 主体には不向き |
| **Howler.js** | 2.2.4 | オーディオ | BGM/SE、スプライト音源、モバイルの自動再生制限対応 | 更新は落ち着いている（安定版） |
| **GSAP** | 3.15.0 | アニメーション | DOM/Canvas どちらにも使える Tween・タイムライン | 独自ライセンス（無償だが MIT ではない） |

## 3. 案の比較

### 案 A：Phaser 4 へ全面移行
- 〇 「ゲームエンジンを使っている」状態に最も近い。演出・音・入力が一体。
- × `src/ui/` をほぼ全部書き直し。テキスト UI を Canvas で組むのは手間（折り返し、ルビ、スクロール、入力欄、画面幅対応）。DOM 要素を重ねる機能はあるが、結局 2 系統を管理することになる。
- × Playwright のテストが DOM セレクタで書けなくなる。
- 工数：大（UI 全面＋テスト作り直し）

### 案 B：PixiJS で「机」だけ Canvas 化＋周辺は DOM（ハイブリッド）
- 〇 ドラッグ・重ね・ルーペ（拡大マスク）・UV（色フィルタ）・スプライトなど**ゲームらしさが欲しい部分だけ**に GPU 描画を使える。
- 〇 規則帳・帳簿・交渉・朝/夜画面は今の DOM をそのまま残せる。`core/` は無変更。
- △ 机の上の「照合（クリックで 2 項目選ぶ）」を Canvas 側で再実装する必要あり。ヒット判定は Pixi のイベントで書ける。
- △ 描画モデルが「毎回作り直す」から「保持して差分更新」に変わる。机部分だけ `GameState` → Pixi オブジェクトの同期関数を書く。
- 工数：中（`counter.ts` の机部分 ＋ 新規 `src/desk/`）

### 案 C：DOM のまま、ゲーム向け小物ライブラリだけ追加
- Howler（音）＋ GSAP or Motion（演出）＋ interact.js（ドラッグ）。
- 〇 最小工数・低リスク。テストもそのまま。
- × ルーペ拡大や UV フィルタのような画像処理系の演出は CSS 頼みで限界がある。「ゲームライブラリを使う」という目的には弱い。
- 工数：小

## 5. 推奨案

**案 B（PixiJS v8 で机だけ Canvas 化）＋ Howler（音）＋ GSAP（Tween）** を推奨する。段階的に入れる。

1. **Step 1：音と演出（案 C 相当、低リスク）**
   - `howler` を入れ、`src/ui/sound.ts` に SE/BGM の再生口を作る。`store.act()` の結果（取引成立・通報・指摘など）に応じて鳴らす。
   - 客の入退場・判子・トーストに GSAP の Tween をかける。
2. **Step 2：机の Canvas 化（本命）**
   - `pixi.js` を導入し、窓口画面の「作業机」領域だけを `<canvas>` に置き換える（新規 `src/desk/`）。
   - 品物・書類・質札を Pixi の `Container` として描き、ドラッグ・前面化を実装。
   - ルーペ：円形マスク＋拡大スプライト。UV ライト：`ColorMatrixFilter` 等で紫外線風の色調と透かし表示。
   - 照合モード：Canvas 内のヒット領域から既存の `act({ type: 'COMPARE', a, b })` を dispatch。`core/` は変更しない。
   - 道具トレイ・交渉パネル・規則帳タブは DOM のまま。
3. **Step 3：アセット**
   - アートが決まったら Pixi の `Assets` で画像を読み込み、絵文字・SVG 顔を差し替え。

### Phaser を選ばない理由
このゲームは「机の上の数枚のカード」と「大量の日本語テキスト」が主役で、物理・カメラ・タイルマップなど Phaser の強みの大半を使わない。全面移行のコストに対してハイブリッドで得られる体験はほぼ同じ。ただし、**今後アクション要素やマップ移動を足す予定があるなら Phaser 4 を再検討**する。

### 注意点
- GSAP は無償だが独自ライセンス（Webflow 社の “Standard No Charge License”）。MIT にこだわるなら Tween は Pixi 用に `@tweenjs/tween.js` 等、DOM 側は Motion で代替可能。
- Pixi は WebGL 前提。描画できない環境向けに、机を従来の DOM 表示にフォールバックできるよう `counter.ts` の既存カード描画は当面残す。
- テスト：机内部の操作は Playwright で座標クリックになる。ロジックは従来どおり `core/` の Vitest で担保し、E2E は「机が表示される」「照合が通る」程度に絞る。
